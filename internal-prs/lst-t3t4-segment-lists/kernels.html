LST MD/LS/T3/T4 pass masks and flat T3/T4 building: per-kernel changes, timing and memory

Before = master 5b4335d798f, after = the PR head cd8b586bed9 (two commits on that master). Per reco category: the kernels before → after, their time, then one memory table. Every kernel listed runs once per event.

Timing: standalone, HLT settings (pT cut 0.8 GeV), CPU 32 streams, GPU (NVIDIA L40) 1 stream, mean of 2 rounds (they agree within 2.1% per kernel and 0.7% per stage). Samples:

  • ttbar: the standalone PU200 ttbar file, 175 events.
  • QCD PU200: 200 events of RelValQCD_Pt_1800_2400_14 PU200 (D121), run through the Phase-2 HLT menu (CMSSW_20_1_X_2026-10-27-2300) into a tracking ntuple; its pixel seeds are the HLT Patatrack pixel tracks.

It is measured with a wait after each kernel in an instrumented build that is not part of the PR; the instrumented and the plain builds give identical track candidates on both samples. A stage time also includes its allocations, memsets and host synchronizations. Memory: LST's own per-event allocation report, 100 ttbar and 200 QCD PU200 events.

On the CPU backends, where a block runs on one thread at a fixed cost, these launches use a single block (the kernels loop over the grid): CountMiniDoublets, CreateMiniDoublets, AddPixelMiniDoubletsToEventKernel, CountMiniDoubletConnections, CreateSegments, FillCompactSegments, CountSegmentConnections, CreateTriplets, CountTripletLSConnections, CreateQuadruplets and RemoveDupQuadrupletsBeforeTC. CreateTripletsFromMatches and RemoveDupQuadrupletsAfterBuild keep several blocks on every backend.

The list kernel costs the same before and after. On the GPU in QCD PU200 the T5 stage is 0.41 ms/event slower (1.14 → 1.54, +36%, in both rounds), outside that kernel; the number of T5s is the same in every event (checked on the CPU). The cause is not traced. The pT3 stage there goes from 0.95 to 1.11 ms. The CPU T5 times and the GPU ttbar ones change by less than 0.6% (the two master rounds of the CPU QCD PU200 T5 stage differ by 0.5%). The whole GPU QCD PU200 event (instrumented build) goes from 38.2 to 8.4 ms.

What does not change:

  • The sizes of the stored MD, LS, T3, T4 and T5 collections, in every event of both samples except one: in QCD PU200 event 115 (200 events checked), 195882 triplets instead of 195883. The track candidates are identical in every event. A stored T4 is 8 bytes smaller (the pair-list column is gone).
  • The T3 creation buffer, within 0.1%.
  • The T5 stage buffers.
  • LST's peak allocation per event: 17.4 (24.7) MB for ttbar and 24.6 (45.5) MB for QCD PU200. It is identical in all but 2 ttbar and 3 QCD events, where it is 0.1 MB lower; the new buffers are never live at the peak.
